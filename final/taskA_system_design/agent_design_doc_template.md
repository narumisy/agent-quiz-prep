# 【智能售后客服知识问答 Agent】系统设计说明

## 一、项目概述

### 1.1 场景背景与痛点

【用 3-5 句话说明场景所在的行业/企业，改造前存在的问题。示例：
某装备制造企业售后客服部门日均接待咨询 800+ 单，80% 为重复性的产品使用与常见故障咨询。客服人员需要同时记忆多款产品手册与 FAQ，培训周期长、响应速度慢、回答口径不一；晚间与节假日无法及时响应，客户满意度持续下滑。】

### 1.2 改造目标

- 【目标1】例如：常见问题自动应答率 ≥ 80%
- 【目标2】例如：客服平均响应时间从 5 分钟降至 30 秒内
- 【目标3】例如：回答统一引用知识库出处，口径一致

### 1.3 改造范围

| 环节 | 改造前 | 改造后 |
|------|--------|--------|
| 用户咨询 | 人工客服逐条回复 | Agent 自动应答，复杂问题转人工 |
| 知识检索 | 人工翻手册 | 知识库向量检索，秒级命中 |
| 口径一致性 | 依赖个人经验 | 统一引用标准文档 |

## 二、方案设计

### 2.1 总体架构

【给出架构说明，可用文字分层描述，也可附架构图】

- 接入层：Web/IM 对话入口（用户提问）
- 智能体层：Agent 智能体（意图识别 → 检索 → 生成 → 转人工）
- 知识层：百炼知识库（产品手册、FAQ、故障处理流程，向量化存储）
- 集成层：工作流编排 + 工具插件（工单系统/转人工 API）
- 模型层：大模型（生成回答 + 引用）

### 2.2 核心流程（Agent 工作流）

1. 用户输入问题
2. 意图识别：判断是否为产品/故障/售后咨询（还是闲聊、无关内容）
3. 知识检索：在知识库中检索相关文档片段
4. 答案生成：依据检索片段生成带引用的回答
5. 兜底处理：未命中知识 → 友好说明并转人工

### 2.3 关键技术点

- 【可写 RAG、向量检索、多轮记忆、工具调用等】

## 三、Agent 功能清单

| 编号 | 功能 | 说明 | 对应百炼组件 |
|------|------|------|--------------|
| F1 | 产品咨询问答 | 依据产品手册回答参数、使用方法 | 知识库 + 智能体 |

| F3 | 多轮对话 | 记住上文，追问时可省略上下文 | 智能体（记忆） |

| F5 | 转人工工单 | 生成工单提交给客服系统 | 工具插件（API） |

## 四、Agent 配置详情

```text
你是【公司名】的售后智能客服助手，负责解答产品使用、功能与常见故障问题。
回答必须基于知识库内容，引用出处；知识库没有的内容不要臆造，应引导用户提供更多信息或转人工。
语气专业、简洁、有耐心。多轮对话时主动结合上文语境。
```
